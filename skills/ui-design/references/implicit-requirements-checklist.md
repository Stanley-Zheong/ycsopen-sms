# ycsopen-sms 隐性需求清单（中后台系统惯例）

企业管理系统的spec很少会把这些写全，但用户拿到成品时会默认它们存在。拆解每个功能模块时，逐条判断"这个模块需不需要这一项"，需要就加进页面清单，不需要也在心里过一遍再跳过（不是所有模块都要全部具备，比如一个纯只读的报表页不需要批量操作）。

本项目中每项判断必须记录在 active phase DESIGN/DECISIONS，并映射到
UI-ELEMENTS、TEST-MATRIX 和最终 `data-testid`。清单不是补造 PRD 权限或
状态的许可；遇到租户边界、计费、消息终态等关键歧义时保持 TODO 打开。

短信业务还要显式判断：手机号/内容脱敏、任务与子消息状态、回执和错误码、
通道与路由来源、发送/到达统计口径、费用影响、重试/取消权限、投诉与退订、
批量/定时任务的部分成功和恢复入口、请求/任务/消息关联标识及复制动作。

## 1. 标识与元信息
- 业务ID/主键是否要展示给用户？（内部数据库自增ID通常不展示；订单号/工单号这类业务编号通常要展示，且常常需要"复制"按钮）
- 创建人/创建时间、最后修改人/修改时间是否要展示？——列表页常做成可选显示列，详情页/日志类页面基本必须有。
- 数据来源标识（如果数据可能来自多个渠道/系统同步，要不要标出来源）？

## 2. 列表页标配
- 搜索：单关键词搜索 vs 多字段组合筛选（状态/时间范围/负责人/标签等），后者是中后台列表页的常态，不要只做一个搜索框就完事。
- 排序：哪些列可排序，默认排序规则是什么。
- 批量操作：是否支持批量选中 + 批量操作（批量删除/批量导出/批量分配/批量审批）？只要列表数据量可能上百条，这条基本是标配。
- 导出：是否需要导出Excel/CSV？导出是导出当前筛选结果还是全部数据，要不要支持自定义导出字段。
- 分页 vs 无限滚动：中后台管理列表默认用分页，除非spec明确是信息流场景。
- 列自定义：是否需要用户自己选择显示哪些列（数据字段多的表格常见需求）。
- 空状态、加载态、错误态的文案和操作引导。

## 3. 表单页标配
- 必填/选填标识，字段级校验规则和错误提示。
- 草稿保存：是否支持未提交先保存草稿？
- 关联数据选择：下拉/搜索选择关联对象时，要不要支持"新建一个"的快捷入口（比如选客户时旁边能直接新建客户）。
- 表单是否有"编辑中防止其他人同时编辑"（乐观锁/编辑锁）的需求，多人协作场景常见。

## 4. 权限与状态
- 页面/区块级权限：登录后即可见 / 特定角色可见 / 特定权限点可见 / 特定业务状态下才显示（比如"仅审批中显示撤回按钮"）——阶段1的页面清单必须把这个写清楚，不能笼统写"需要登录"。
- 数据行级权限：用户是否只能看到自己负责的数据，还是能看到全部（常见于CRM、工单类系统）。
- 操作按钮的禁用态：权限不足或状态不允许时，按钮是隐藏还是置灰+提示，两种处理方式要在整个系统里保持一致。

## 5. 审计与追溯
- 操作日志/审计日志页面：谁在什么时候对什么数据做了什么操作，敏感操作（删除、权限变更、数据导出）尤其要有。
- 软删除与回收站：删除是物理删除还是先进回收站可恢复，删除类操作默认建议二次确认弹窗。

## 6. 消息与IM对接
- 系统内通知中心（消息小红点、通知列表）。
- 外部IM对接：钉钉/飞书/企业微信——常见诉求包括：账号免密登录/绑定、审批消息推送到IM群或个人、通过IM机器人接收告警。如果spec提到"审批""告警""提醒"这类词但没说渠道，要主动询问或在假设里注明按站内消息处理。
- 邮件/短信通知作为IM的替代或补充渠道。

## 7. 角色与账号管理
- 用户管理页面：角色分配、权限点配置、账号启用/禁用、密码重置。
- 组织架构/部门管理：如果系统权限跟部门/层级挂钩，需要有组织架构维护页面。
- 登录页与登录态：单点登录(SSO)/账号密码登录/IM扫码登录，多因素认证要不要支持。

## 8. 系统与设置
- 全局设置页（品牌信息、通知规则、集成配置）。
- 多语言/多时区（面向跨地区团队的系统常见，spec没提但用户群体跨地区时要主动提出问题）。
- 数据看板/首页工作台：绝大多数中后台系统都有一个登录后的"工作台"首页，聚合待办、关键指标、快捷入口，spec里即使没单独提，也大概率需要。

## 9. 反馈与确认
- 破坏性操作（删除/批量操作/驳回）默认要二次确认弹窗，并清楚说明后果。
- 异步任务（导入导出、批量处理）要有进度反馈和结果通知，不能操作完就没有下文。
