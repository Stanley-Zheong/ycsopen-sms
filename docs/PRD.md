### 1.3 名词解释/术语表（Glossary）

| 术语 | 说明 |
|---|---|
| 机构用户 / 租户 | 使用本平台发送短信的企业客户，享有独立的账户余额、模板、签名、黑名单、报表等隔离数据 |
| 通道 | 平台对接的单条上游运营商/通道商链路，含协议类型、账号、密价、限速等属性 |
| 通道池 / 通道组 | 一组可互为主备或参与权重路由的通道集合 |
| 路由规则 | 决定一条短信应该被分配到哪个/哪些通道发送的策略配置 |
| 签名 | 短信发送方标识，如"【优创硕安】"，需实名审核，一个机构可拥有多个签名 |
| 模板 | 已审核通过的短信文案模式（含变量占位），一个机构可拥有多个模板，发送时引用签名+模板 |
| CMPP | 中国移动短信网关接入协议（China Mobile Peer to Peer），本平台上游对接移动使用，同时开放给下游客户可选接入 |
| SGIP / SMGP | 中国联通 / 中国电信的短信网关接入协议 |
| 上行 | 终端用户回复短信到平台/企业的消息 |
| 下行 | 平台/企业发送给终端用户的短信 |
| 回执 / 状态报告 | 运营商返回的短信送达状态（成功/失败/时延等） |
| 预付费 | 机构先充值到账户余额，发送时实时扣费，余额不足则拒绝提交 |
| 后付费 | 机构先使用后按账期（月/季）结算，需授信额度与信用管理 |
| 黑名单 | 禁止向其接收发送短信的号码清单，分系统级、机构级、第三方风险名单三类 |
| TPS | 每秒事务数（Transactions Per Second），本文中指每秒短信处理/发送条数 |
| **投诉占比** | 统计周期（默认按自然月）内，某通道或某机构关联的投诉工单数量 ÷ 该通道或机构当月发送量，用于衡量通道/机构的合规健康度；超过预警阈值需重点关注（详见 7.2 节） |
| 试用期 | 机构完成注册审核后、正式签约前的过渡阶段，享有限定条数额度与有效期的免费试用 |
| 签约 | 机构与平台确定正式合作关系（计费模式、价格、账期等）的商务动作 |

## 2. 项目背景与目标 (Background & Objectives)

### 2.1 项目背景 (Background)

优创硕安需要建设一套自营的**短信通道平台系统**，向上对接多家运营商 / 短信通道商（不同协议、不同计费方式），向下服务企业客户（机构用户），支持 HTTP 和 CMPP 两种下游接入协议。平台需要同时具备"通道商"（对上游议价、路由分发、容灾）和"SaaS 短信服务商"（面向企业客户的产品化、计费、合规审核）两种能力，是典型的**多租户、多通道、可运营的短信中台**。

本地已有一套较完整的原型实现（Spring Boot 3 + Java 21 后端，React 18 + TypeScript 双前端，位于 `Documents/codebases/ycsan-sms/`），本 PRD 在此基础上系统化梳理并补齐正式的产品需求定义，作为后续开发排期、评审与验收的依据。

### 2.2 核心目标 (Goals)

1. **稳定的通道能力**：对接多个上游运营商/通道商，支持不同协议（CMPP/SGIP/SMGP/HTTP）与不同计价体系，具备智能路由、失败重发、熔断切换能力。
2. **双协议下游接入**：为企业客户提供 HTTP API（主）与 CMPP 协议（可选）两种接入方式。
3. **合规风控**：签名/模板实名审核、黑名单检测（系统级 + 机构级 + 第三方风险名单）、内容审核（敏感词过滤）、频次限流，防止违规发送与投诉。
4. **灵活计费**：同时支持预付费（余额扣费）与后付费（账期结算）两种商业模式。
5. **完整的运营配套**：为系统管理员、平台运营、财务、机构（企业）用户分别提供匹配其职责的 Web 管理端功能，覆盖机构从注册到终止的全生命周期。
6. **满足既定性能与合规指标**：同步发送峰值 ≥1000 条/秒，具备日处理 ≥10 万条的基线容量并可平滑水平扩展；核心业务数据留存 2 年以上；数据加密存储。

### 2.3 量化指标（KPIs/Metrics）

| 指标 | 目标值 | 衡量方式 |
|---|---|---|
| 短信到达率（送达成功率） | ≥ 99%（国内三网） | 回执详单中"已送达"状态占比 |
| 同步发送峰值处理能力 | ≥ 1000 条/秒（TPS） | 压测报告 |
| 日处理能力基线 | ≥ 10 万条/天，可水平扩展 | 生产环境统计聚合表 |
| API 提交响应时间 | P95 < 200ms（不含运营商侧处理时延） | 网关侧监控 |
| 系统可用性 | ≥ 99.9% | 全年不可用时长统计 |
| 通道故障自动切换时间 | ≤ 30 秒（从熔断触发到备用通道生效） | 通道监控日志 |
| 签名/模板首次审核时长 | ≤ 1 个工作日 | 审核中心时间戳统计 |
| 月度对账差异率 | < 0.1% | 对账单差异记录 |
| **通道 / 机构月度投诉占比** | 均 **< 千分之三（0.3%，默认阈值，可配置）** | 详见 7.2 节投诉占比看板 |
| 数据留存年限 | ≥ 2 年 | 归档策略审计（10.12 节） |

### 2.4 项目范围（In Scope / Out of Scope）

**In Scope**
- 短信（含验证码、通知、营销、国际短信）的提交、路由、发送、状态回执全链路。
- 上游通道管理（CMPP/SGIP/SMGP/HTTP 等协议接入运营商或通道商）。
- 下游 HTTP API 与 CMPP Server 网关。
- 签名、模板的多签多模板管理与审核流程。
- 路由引擎（含黑名单检测、频次控制、内容审核、号码归属/携号转网识别、分流与重发规则）。
- 计费账务（预付费余额、后付费账期、对账、结算、发票）。
- 机构全生命周期管理（注册试用、签约、月度对账、费用预警、投诉预警与暂停、终止）。
- 平台管理后台（系统管理员、运营、财务）与机构端（企业客户）两套 Web 系统。
- 数据统计、详单查询、导出、告警监控、操作审计、数据加密存储。

**Out of Scope（暂不包含，后续迭代评估）**
- 语音短信、彩信（MMS）、国际短信的完整本地化合规体系（预留扩展点，不在首期实现）。
- 智能客服/工单系统（投诉处理仅做记录与流转，不含在线客服系统）。
- 短信内容 AI 生成/营销自动化能力。
- 多语言国际化（i18n）与用户自定义拖拽式仪表盘布局（预留扩展点，见 6.3、7.2 节）。

### 2.5 分阶段实施路线图

#### 阶段一（高优先级，约 3 个月）—— 中台能力与基础通路

- 账号权限、机构管理、签名模板管理与审核流程闭环；机构注册与试用流程（F-2.1/F-2.2/F-2.8）。
- 至少 1 个上游 CMPP 通道 + 1 个上游 HTTP 通道真实对接，打通"提交→路由→发送→回执"全链路。
- 路由引擎基础能力：黑名单检测（系统级+机构级）、内容审核管理（敏感词库）、频次拦截、基础分流规则。
- HTTP API 下游接入（单条/批量发送、状态查询、Webhook 回调）。
- 基础告警监控、三类仪表盘（实时监控大屏/关键指标概览/告警信息展示）与数据详单查询（发送/群发/回执/上行详单）。

#### 阶段二（中优先级，约 6 个月）—— 多通道路由与计费闭环

- 接入更多运营商/通道商，完善分流、权重路由、失败重发与熔断策略；通道暂停/恢复能力（F-4.7）。
- 第三方黑名单风险检测服务对接，纳入路由前置检测。
- 计费账务模块：预付费扣费、后付费账期、对账、结算、发票；签约管理与费用预警（F-2.9/F-8.10）。
- 上行短信处理（关键词识别、退订自动入黑名单与退订记录查询、上行推送与重推）。
- 数据统计分析与自定义报表、工具管理体系（短链生成与短链审核、状态码/号段管理）。
- **通道/机构月度投诉占比看板上线**（F-11.9），超阈值高亮预警。

#### 阶段三（低优先级，约 9 个月）—— 下游 CMPP 与体验优化

- 下游 CMPP Server 网关开放给试点机构。
- 携号转网号码库完善、免审规则优化。
- 投诉管理闭环、机构级投诉预警自动暂停（F-9.5）、告警策略精细化、数据归档策略落地（满足 2 年+留存要求）。
- 机构终止管理全流程打通（F-2.10）。
- 性能压测与调优，确保达到 1000 TPS 峰值与既定可用性指标。

## 3. 用户角色与场景分析 (User Personas & Scenarios)

### 3.1 用户角色定义 (User Roles)

| 角色 | 归属 | 核心职责 |
|---|---|---|
| **系统管理员**（Admin） | 平台方 | 平台账号/角色/权限体系、系统参数配置、全局审计、最高权限 |
| **运营人员**（Operator） | 平台方 | 通道管理、路由/黑名单/内容审核等风控规则配置、签名模板审核、投诉处理、上行数据处理、平台侧统计分析、告警处置 |
| **财务人员**（Finance） | 平台方 | 机构账户/充值审核、对账、结算、账单出具、成本核算、发票管理、费用预警 |
| **机构管理员**（Tenant Admin） | 机构（企业客户） | 机构内子账号与 API Key 管理、提交签名/模板申请、查看账单对账、配置回调与黑名单 |
| **机构业务用户**（Tenant User） | 机构 | 在线发送、批量发送、查看本机构详单与统计 |
| **机构开发人员** | 机构 | 通过 HTTP API / CMPP 集成短信能力，管理 API Key / CMPP 接入参数 |
| **系统集成方** | 外部 | 通过 API/CMPP 调用短信服务、接收 Webhook 回调或 CMPP DELIVER 上行/回执推送 |

### 3.2 权限模型

- 采用 **RBAC**（基于角色的访问控制），权限资源分为菜单（MENU）、按钮（BUTTON）、接口（API）、数据（DATA）四类，可自定义角色并组合权限点；具体安全实现要求见 6.2 节。
- 平台侧角色（系统管理员/运营/财务）与机构侧角色（机构管理员/业务用户）在数据权限上严格隔离：机构侧用户只能访问 `org_number` 归属于本机构的数据；平台侧用户按角色可访问全平台或按分配范围的数据。
- 关键操作（余额调整、角色权限变更、签名/模板审核、通道配置变更）需记录操作日志，支持审计追溯。

### 3.3 核心使用场景 (User Scenarios)

**场景一：机构开发人员集成验证码发送**
某电商机构的开发人员小李需要在用户注册流程中接入短信验证码。他在机构端"配置管理"申请 API Key，获得 App Key/App Secret 后按 9.1 节签名规范调用发送接口，选用已审核通过的"验证码"模板与签名，传入手机号与验证码变量。系统按预付费余额实时扣费并返回消息 ID，小李通过状态查询接口或 Webhook 回调确认送达情况（对应 F-2.6、F-6.1、F-6.4、F-6.6）。

**场景二：运营人员审核签名与处理投诉**
运营人员小王每天在"审核中心"处理机构提交的签名/模板申请，核对品牌权属证明与内容合规性；某日收到监管转来的一起营销短信投诉，小王在"投诉管理"登记工单，核实后将涉事号码加入黑名单并暂停该机构下的问题签名（对应 F-3.2、F-3.5、F-9.1~F-9.3）。

**场景三：财务月度对账与费用预警处理**
财务人员小张在每月初为所有机构生成上月对账单，逐一核对发送量与计费金额；系统同时提示某后付费机构消费已达授信额度的 85%，小张主动联系机构提醒续费或提额（对应 F-8.5、F-8.10）。

**场景四：机构从注册到签约的全流程**
新机构提交营业执照、法人证件、联系人信息、短链域名与商标所有权证明后，运营审核通过，系统自动开通 500 条 / 14 天的试用额度；机构在试用期内验证效果满意后，与商务经理确定预付费单价并完成正式签约，账号解除试用限制（对应 F-2.1、F-2.2、F-2.8、F-2.9，详见第 12 章生命周期流程）。

**场景五：终端用户回复"TD"退订营销短信**
终端用户收到某机构的营销短信后回复"TD"要求退订。平台上行处理服务识别退订关键词，自动将该号码加入发起机构的黑名单，生成退订记录并通过 Webhook 通知机构，机构侧应用同步更新自身用户名单，避免后续再次触达（对应 F-10.2、F-7.9）。

**场景六：运营发现某通道投诉占比超标并暂停**
运营人员在"关键指标概览"仪表盘的"通道投诉占比"看板中看到某上游通道当月投诉占比达到 0.42‰，超过千分之三的预警线并被标红置顶；点击下钻查看该通道近期投诉工单后，运营判断问题集中在某类营销内容上，遂对该通道执行暂停操作，系统自动将在途任务切换至备用通道（对应 F-11.9、F-4.7、F-5.9）。

## 4. 产品整体架构与流程 (Product Architecture & Flow)

### 4.1 信息架构总览 (Information Architecture)

平台由"平台管理后台（Admin Portal）"与"机构端（Tenant Portal）"两套 Web 应用构成，顶层功能划分为：数据概览（仪表盘）、账号与权限、机构管理、通道与路由、审核中心、验证规则（风控）、上行数据、数据详单、数据统计、财务中心、告警管理、工具管理、系统管理十三大模块；机构端则聚焦发送管理、模板签名、账户财务、配置管理、上行查询等自助服务功能。完整菜单层级见第 8 章 Web 管理端信息架构。

### 4.2 分层架构

```
接入层（Access Layer）
  ├─ HTTP/HTTPS API 网关（下游 REST 接入，ALB 七层入口）
  ├─ CMPP Server 网关（下游协议接入，NLB/CLB 四层 TCP 入口）
  └─ Web 控制台（平台管理后台 + 机构端）

业务层（Business Layer）
  ├─ 账号与租户服务（用户、角色、权限、机构、API Key/协议凭证）
  ├─ 产品与策略服务（短信产品：验证码/通知/营销/国际，绑定单价/速率/时间窗）
  ├─ 消息管理服务（提交、状态机、详单）
  ├─ 路由与调度服务（黑名单检测、频控、内容审核、号码归属识别、路由分流、重发/熔断）
  ├─ 计费与账务服务（预付费扣费、后付费账期、对账、结算）
  └─ 合规与风控服务（签名/模板审核、免审规则、投诉处理）

通道层（Channel Layer）
  ├─ CMPP 上游连接器（移动）
  ├─ SGIP 上游连接器（联通）
  ├─ SMGP 上游连接器（电信）
  └─ HTTP/REST 上游连接器（云通道商/国际短信商）

基础设施层（Infrastructure Layer）
  ├─ MySQL（业务数据，主库 + 只读分离 + 分区/归档）
  ├─ Redis（限流计数、缓存、路由/黑名单/内容审核热数据）
  ├─ 消息队列 RocketMQ/Kafka（提交队列、发送队列、回执队列、统计队列）
  ├─ 对象存储（导出文件、归档冷数据）
  └─ 监控告警（Prometheus/Grafana + 日志采集 ELK/Loki）
```

### 4.3 业务流程图（核心数据流）

1. **下行提交流**：下游 HTTP/CMPP 接入 → 鉴权/参数校验/签名模板校验/黑名单与频控前置检查 → 写入 `message_submit` 并入队 → 号码归属识别（携号转网感知）→ 路由服务按规则选通道 → 生成 `message_task` → 通道连接器投递上游 → 更新状态为已提交/已发送。
2. **状态回执流**：上游回执（状态报告/DELIVER）→ 通道连接器解析 → 状态处理服务更新任务与提交记录状态 → 按需触发下游 Webhook 回调或 CMPP DELIVER 推送 → 计费确认/冲正。
3. **上行消息流**：终端用户回复 → 上游网关 → 平台上行处理服务 → 关键词识别/退订处理 → 推送至机构回调地址，失败则进入重推队列。
4. **配置生效流**：Web 控制台变更（路由规则/黑名单/内容审核/通道参数等）→ 写库并广播缓存失效/更新 → 路由与风控服务实时生效（秒级）。
5. **投诉占比统计流**（新增）：投诉工单登记（F-9.1）与发送统计聚合表（10.11 节）按机构/通道维度每日汇总 → 月度滚动计算投诉占比 → 写入投诉占比统计视图 → 超阈值记录推送至仪表盘（F-11.9）与告警规则（F-12.1）。

### 4.4 用户操作流程（User Task Flow）

**Task Flow A：机构通过 HTTP API 发送验证码短信**

1. 机构开发人员在机构端"配置管理-API Key 管理"创建 API Key，获取 App Key/App Secret。
2. 调用 `发送短信` 接口，携带手机号、模板编码、变量参数与签名规范（见 9.1 节）。
3. 网关校验签名、时间戳、nonce、IP 白名单、限流阈值 → 通过则进入路由引擎。
4. 路由引擎依次执行：黑名单检测 → 内容审核 → 频次拦截 → 号码归属识别 → 分流选通道（见 5.5 节流程图）。
5. 任一环节被拦截，接口同步返回对应错误码；全部通过则受理成功，返回消息 ID，异步进入发送队列。
6. 通道连接器投递上游，收到回执后更新状态；若配置了 Webhook，异步推送状态报告给机构。

**Task Flow B：机构注册并申请签名/模板**

1. 机构在官网/机构端提交注册资料（简称、全称、营业执照、法人身份证、联系人信息、短链域名所有权证明、商标所有权证明）。
2. 运营人员在"机构管理"审核资料真实性，通过后系统自动开通试用账号并配置试用额度与有效期。
3. 机构在"签名管理""模板管理"分别提交签名、模板申请。
4. 运营人员在"审核中心"分别审核，通过后签名/模板状态变为"已通过"，签名同步进入通道报备流程。
5. 机构使用已通过的签名+模板发起发送（关联 Task Flow A 第 2 步）。

**Task Flow C：运营处理一起投诉并暂停涉事通道**

1. 运营在"投诉管理"登记一起来自监管/用户的投诉工单，关联涉事机构、签名、发送记录。
2. 运营核实投诉真实性，将涉事号码加入黑名单（联动 F-9.3）。
3. 运营查看"关键指标概览"仪表盘中该通道的当月投诉占比（F-11.9），确认超过预警阈值。
4. 运营对该通道执行"暂停"操作（F-4.7），路由引擎自动将在途任务切换至备用通道（F-5.9）。
5. 问题解决后，运营对通道做小流量测试（F-4.3），确认无误后手工恢复通道。

### 4.5 技术栈（沿用现有原型选型，作为技术选型建议）

- 后端：Spring Boot 3.x + Java 21，微服务拆分为 SMS Gateway（接入/鉴权/限流）与 SMS Core（业务核心）。
- 数据库：MySQL 8.0（云 RDS），历史数据分区表 + 冷热分离归档。
- 缓存：Redis 7.x（限流、路由/黑白名单/内容审核缓存）。

- 部署：Docker + Kubernetes（Helm），HTTP 走七层 ALB，CMPP 长连接走四层 NLB/CLB TCP 监听。

### 5.3 签名与模板管理（F-3）

| F-3.4 | 模板申请 | 机构提交模板内容（含变量占位符，如 `${code}`）、模板类型（验证码/通知/营销）、关联签名、参数校验规则、申请说明 |
| F-3.5 | 模板审核 | 运营人员在"模板审核"列表中按模板名称/机构代码/审核状态/模板类型筛选，逐条查看模板内容、申请机构、关联签名、模板类型、审核状态、提交时间；支持通过/驳回/修改意见，重点核查内容规范、变量安全性、是否涉敏 |
| F-3.6 | 免审规则 | 支持为优质机构配置签名免审、内容免审、账号免审三类免审规则，设置有效期与使用范围；免审记录仍需留痕 |
| F-3.7 | 发送前置校验 | 任一下行提交（HTTP 或 CMPP）必须引用状态为"已通过"的签名与模板，内容需匹配模板变量模式；国内通道不允许自由文本发送（国际/特殊通道可按策略放开） |
| F-3.8 | 签名/模板统计 | 展示各签名、模板的使用频次、成功率、驳回率等统计 |

| 关联签名 | 下拉选择 | 是 | — | 必须选择本机构已通过审核的签名 | 无 |
| 参数校验规则 | 字符串 | 否 | 正则表达式 | 语法合法性校验 | 无限制 |

**状态机（签名/模板审核状态）**

```
待审核 ──(运营通过)──▶ 已通过（长期有效，可被引用发送）
待审核 ──(运营驳回)──▶ 已驳回 ──(机构修改重新提交)──▶ 待审核
已通过 ──(投诉联动下线，F-9.3)──▶ 已停用
```

### 5.5 路由引擎（F-5）—— 含黑名单检测

路由引擎是下行消息从"提交"到"选定发送通道"之间的核心决策链路，按以下**顺序执行**（前置拦截项任一命中即拒绝/丢弃提交，不进入下一步）：

```
提交 → ① 鉴权/参数校验 → ② 签名+模板合规校验 → ③ 黑名单检测（系统级/机构级/第三方风险名单）
   → ④ 内容审核检测 → ⑤ 频次拦截检测 → ⑥ 号码归属识别（含携号转网） → ⑦ 分流规则匹配选通道
   → ⑧ 通道健康度/权重决策 → ⑨ 生成发送任务 → （失败）⑩ 重发规则 → 备用通道/终止
```

| 编号 | 功能 | 验收标准 |
|---|---|---|
| **F-5.1** | **黑名单检测（路由前置拦截，硬性要求）** | 路由必须在选择通道**之前**完成黑名单检测，命中任一黑名单则直接拦截，不产生发送任务，并记录拦截原因；检测源包括：① **系统级黑名单**（全平台生效，如已确认骚扰/涉诈号码）；② **机构级黑名单**（机构自行维护，仅对该机构生效，如退订用户）；③ **第三方风险名单服务**（对接外部黑名单/投诉风险检测 API，如"泰迪短信黑名单"类服务：按号码查询风险分值，分值达到阈值判定为黑名单，支持单号检测与批量检测两种接口，返回拦截来源如"风险拦截/行为预测拦截/用户反馈拦截/靠号拦截/高敏拦截"等分类）。三类检测结果按"任一命中即拦截"合并判定，命中优先级与拦截原因需在详单中可追溯 |
| F-5.2 | 黑白名单管理 | 页面同时管理黑名单与白名单，头部统计"黑名单数/白名单数"；列表字段含手机号码、原因、**来源**（手工添加/批量导入/退订自动加入/第三方风险名单/投诉联动）、状态、创建时间；支持按手机号码/来源/状态筛选查询；支持手工增删、**批量导入**、**导出**；白名单优先级高于黑名单（白名单命中则跳过黑名单拦截） |
| F-5.3 | 第三方黑名单服务配置 | 支持配置对接的第三方风险名单服务地址、鉴权凭证、检测等级（基础/中级/高级）、命中阈值分值、超时降级策略（第三方接口超时/异常时，按配置决定"放行"或"按最近缓存结果判断"，避免因外部依赖故障导致发送链路整体不可用） |
| F-5.4 | 拦截统计与误拦分析 | 展示各类黑名单拦截量、拦截率、按来源（系统/机构/第三方）分布，支持申诉与误拦标记 |
| **F-5.5** | **内容审核管理（敏感词库与内容安全，路由前置拦截）** | 对应验证规则模块中的"内容审核管理"页面，是运行时对每条提交内容做实时安全扫描的能力（区别于 F-3 的资质/资源审核，见 5.3 节说明）。页面头部展示统计卡片：**词库总数、今日拦截量、拦截率、词库覆盖率**；词库列表字段含：敏感词、**分类**（违法/金融/营销/政治/色情等）、**级别**（高/中/低）、替换词、**处理动作**（拦截/替换/告警）、**作用域**（全平台/指定机构/指定产品）、状态（启用/禁用）、创建时间；支持按敏感词/分类/级别/处理动作/状态筛选查询；支持单条增删改、**批量导入词库**、**导出词库**；命中后按处理动作执行拦截/替换/仅告警三种模式之一，并计入统计卡片；词库变更支持热更新，秒级生效 |
| F-5.6 | 频次拦截 | 对应"频次拦截管理"页面，头部统计卡片：活跃规则数、今日拦截量、拦截率、规则命中率；规则字段含规则名称、**限制类型**（手机号码/机构级别/IP地址/内容相似度等）、限制次数（如"10次/1分钟"）、**处理动作**（拦截/延迟/告警三选一）、状态（启用/禁用）、创建时间；支持按规则名称/限制类型/处理动作/作用域/状态筛选，支持批量导入与导出规则；支持白名单豁免。本规则同时承担"防刷机制"职责（见 6.2 节） |
| F-5.7 | 号码归属地与携号转网识别 | 维护本地号段库（前 3-7 位映射运营商/省市），支持对接实时携号转网查询接口并缓存结果；查询失败时按号段库降级判断 |
| F-5.8 | 分流规则（路由策略） | 支持按运营商、号段、机构、内容关键词、时间段等多维度条件配置路由目标（单通道/通道池/权重分配），条件不匹配时走默认通道 |
| F-5.9 | 主备与熔断 | 通道池内支持主备策略与权重路由；实时统计各通道成功率/时延，超过阈值自动熔断并切换备用通道，异常解除后自动回切 |
| F-5.10 | 重发规则 | 按错误码分类配置是否重发、重发间隔、最大重发次数；重发记录可追溯，避免同号码同内容短时间内被重复触达 |

| F-6.11 | 批量导入群发 | 支持通过文件（Excel/CSV）导入号码及个性化变量，创建批量发送任务 |
| F-6.12 | 定时/周期任务 | 支持设置定时发送时间、任务优先级；任务执行中可暂停/恢复/取消；异常任务支持重启 |

### 5.8 计费与账务（F-8，财务角色主导）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F-8.1 | 预付费模式 | 机构充值后计入账户余额；每次提交前预扣费用/冻结额度，发送成功确认扣费，失败且不计费的场景自动冲正释放额度；余额不足拒绝新提交并可配置低余额告警 |
| F-8.2 | 后付费模式 | 机构按约定账期（周期/月结）使用服务，设置授信额度上限，超额可配置拦截或人工审批放行；周期结束生成账单供对账确认 |

| F-8.4 | 消费流水 | 每笔计费生成消费记录，关联具体发送任务，支持按机构/时间/业务类型统计 |
| F-8.5 | 对账 | 财务人员可按机构、账期生成对账单（发送量、成功量、计费量、金额），支持与机构侧自核对账单据核对确认，标记差异并处理 |
| F-8.6 | 结算 | 后付费机构账期结束后由财务发起结算，生成结算单，支持结算状态跟踪（待结算/已结算/已收款） |
| F-8.7 | 发票管理 | 支持机构申请开票、财务开票登记与状态跟踪 |
| F-8.8 | 成本与利润核算 | 基于各通道实际成本单价与机构计费单价，核算按机构/通道/时间维度的成本、收入、利润 |
| F-8.9 | 余额变动审计 | 记录所有余额变动的时间、金额、类型、操作人，支持财务审计导出 |
| **F-8.10** | **费用预警（费用监管）** | 财务/运营可配置费用预警规则：预付费机构余额低于设定阈值（金额或"预计可用天数"）时触发预警；后付费机构消费金额接近授信额度设定比例（如 80%/95%）时触发预警；预警触发后按配置渠道通知机构与财务/运营，并在仪表盘（F-11.6/F-11.7）中可见；超过授信额度可配置为自动拦截新提交或转人工审批放行 |

**状态机（对账/结算状态）**

```
待确认 ──(机构/财务双方核对无误)──▶ 已确认 ──(后付费，财务发起结算)──▶ 待结算 ──▶ 已结算 ──▶ 已收款
待确认 ──(存在差异)──▶ 有差异 ──(差异处理完毕)──▶ 待确认
```

### 5.15 页面级异常流与边界情况（Edge Cases & Exception Flows，跨模块通用规范）

| 场景 | 处理规范 |
|---|---|
| 网络中断 / 请求超时 | Web 端统一提示"网络异常，请检查网络后重试"，提供"重试"按钮；HTTP API 调用方超时后应按幂等设计（同一 `业务流水号` 重复提交不重复计费/重复发送），网关侧对超时请求记录日志便于排查 |
| 服务器 500 / 内部错误 | 前端展示统一错误页/提示条"系统繁忙，请稍后再试"，不暴露堆栈信息；后端记录 `traceId` 并触发告警（F-12.1），运营/研发可按 `traceId` 追踪全链路日志 |
| 列表数据为空 | 统一展示空状态占位图 + 引导文案（如黑白名单列表"暂无数据"，参考现有页面设计），批量导出等操作按钮置灰 |
| 高并发限流 | 触达 API 限流阈值（F-6.5）返回 HTTP 429 及标准错误结构，提示"请求过于频繁，请稍后再试"；控制台侧手工发送/批量导入超过单机构并发上限时提示排队或延迟处理 |
| 上游通道超时/异常 | 由 F-5.9 主备与熔断机制自动切换备用通道，不阻塞下游提交；连续失败触发 F-4.3 健康检查告警 |
| 第三方风控/黑名单服务异常 | 按 F-5.3 配置的降级策略处理（放行或按缓存结果判断），避免因外部依赖故障导致发送链路整体不可用，并记录降级事件供事后复核 |
| 导出任务失败 | 导出中心（F-7.8）标记任务状态为"执行失败"并展示失败原因，支持一键重试；大数据量导出超时自动拆分为多个子任务 |
| CMPP 长连接断线 | 连接器自动按退避策略重连，重连期间的待发消息进入本地缓冲队列或降级走 HTTP 通道（如已配置备用通道） |
| Webhook 回调失败 | 按指数退避策略自动重试（默认 5 次），全部失败后记录为"推送失败"（F-7.7），支持机构侧或运营手工重推 |
| 审核类表单校验失败 | 表单内联提示具体错误字段与原因（如"统一社会信用代码格式不正确"），禁止提交，不整体刷新页面 |

## 6. 非功能性需求 (Non-Functional Requirements)

### 6.1 性能要求 (Performance)

| 指标 | 要求 |
|---|---|
| 同步发送峰值处理能力 | ≥ 1000 条/秒（TPS） |
| 日处理能力（容量规划基线） | ≥ 10 万条/天，作为初期容量规划的最低保障线；系统需具备水平扩展能力以支撑超出该基线的业务增长（峰值 1000 TPS 理论日容量远高于此基线，10 万条/日为规划时的最低验收口径，非上限） |
| API 响应时间 | 提交类接口 P95 < 200ms（不含运营商侧处理时延） |
| 系统可用性 | ≥ 99.9% |
| 通道健康检查周期 | ≤ 1 分钟一次心跳/测试报文 |

> 说明：需求原文中"同步发送速率支持1000条/秒，单日10万条"两个指标数量级存在明显差异（按1000条/秒峰值理论上限单日可达 8640 万条），评审时建议与业务方确认"单日10万条"具体含义（例如：是否为单机构默认配额、是否为现阶段实际业务量预估、还是容量规划的保底线）。本 PRD 暂按"最低容量基线，非上限，可扩展"处理，待需求方确认后更新。

### 6.2 安全性 (Security)

- 全链路 HTTPS/TLS 加密传输；CMPP 长连接层面做 IP 白名单与账号鉴权。
- API 鉴权采用签名机制防篡改、防重放；控制台采用 JWT + RBAC（权限模型详见 3.2 节）。
- **防刷机制**：HTTP API 限流（F-6.5）与频次拦截规则（F-5.6）共同承担防刷职责，按号码/机构/IP 多维度限制发送频率，超限拦截并记录。
- 签名/模板强制实名审核，国内通道禁止自由文本发送，满足工信部及运营商关于短信签名实名制、模板报备制的监管要求。
- 全量操作日志与安全审计，满足内外部审计追溯要求。

#### 6.2.1 数据加密存储（硬性要求）

| 数据类别 | 涉及字段（对应第 10 章数据字典中标注 🔒 的字段） | 存储要求 |
|---|---|---|
| 身份类敏感信息 | 法定代表人/联系人身份证号、身份证正反面图片、营业执照图片 | 数据库字段级加密（AES-256，信封加密，密钥由 KMS 托管）；证件图片以对象存储加密桶保存，访问需临时授权（STS）URL，禁止公开直链 |
| 联系方式 | 用户手机号、机构联系人手机号、短信发送/上行/详单中的终端手机号 | 数据库字段级加密存储；日志与非必要查询场景下按规则脱敏展示（如 138\*\*\*\*1111），仅授权角色可查看完整号码，查看行为记入操作日志 |
| 账号密钥类 | 用户登录密码、API Key 的 App Secret、CMPP/上游通道账号密码 | **密码类采用单向哈希（bcrypt/Argon2）不可逆存储，而非 MD5+盐等已被业界证明弱化的方案**；密钥类使用对称加密存储，仅在鉴权计算时解密使用，不落明文日志 |
| 财务类信息 | 充值交易号、发票信息、账户余额变动记录 | 数据库字段级加密 + 访问权限限定财务/管理员角色，操作留痕不可篡改（关键字段变更需双人复核） |
| 传输层 | 全部内外部接口 | 强制 TLS 1.2+；内部服务间调用建议 mTLS；CMPP 明文协议本身不可加密，须叠加 IP 白名单 + VPC/专线隔离弥补协议层缺陷 |
| 密钥管理 | 加密密钥、KMS 主密钥 | 密钥与数据分离存储，使用云厂商 KMS 或自建 HSM 托管主密钥，支持密钥轮换；应用侧不持久化明文密钥 |
| 备份与归档 | 10.12 节归档至对象存储的历史数据 | 归档文件同样加密存储，导出文件（F-7.8/详单导出）支持加密与访问口令，防止批量数据泄露 |

- 加密范围覆盖"在途"（传输层 TLS/mTLS）与"静态"（数据库字段级加密、对象存储加密、归档加密）两个维度，缺一不可。
- 敏感字段的加密/解密统一收敛到数据访问层，业务代码不直接接触密钥，降低误用与泄露面。
- 定期（如季度）进行密钥轮换与加密策略审计，作为安全合规检查项纳入运营巡检。

### 6.3 兼容性与环境 (Compatibility)

- **前端浏览器支持**：Chrome、Edge、Safari 最新两个大版本；不专门适配 IE。屏幕适配以桌面端 1366×768 及以上分辨率为主，管理后台不做移动端响应式优化（机构端概览页可做基础自适应）。
- **移动端 App**：本期不提供独立原生 App，机构端仅提供 Web 版本；如后续规划 App，需另行评估 iOS/Android 最低系统版本要求。
- **多语言国际化**：本期默认仅支持简体中文，界面文案、错误提示、导出文件均为中文；数据库设计预留 `locale` 类扩展字段，为后续国际化改造留出空间，但不在本期实现（见 2.4 节 Out of Scope）。
- **时区处理**：系统内部统一以 UTC+8（北京时间）存储与展示时间戳；涉及国际短信/跨境机构场景时，发送时间与回执时间需额外记录时区标识，避免归属地不同导致的时间误判。

### 6.4 可靠性与灾备 (Availability)

- 关键服务（接入层、路由服务、通道连接器）无状态化部署，支持多副本水平扩展。
- 上游通道具备主备/多通道容灾能力，单通道故障不影响整体发送能力，故障自动切换时间窗 ≤ 30 秒（见 2.3 节 KPI）。
- 数据库主从/读写分离，缓存与消息队列采用云托管高可用实例。
- 部署跨可用区，支持灰度发布与快速回滚。

### 6.5 可扩展性

- 通道连接器插件化，新增运营商/协议只需新增连接器实现，不影响既有链路。
- 路由规则、计费规则、审核规则均配置化，避免硬编码。
- 微服务架构支持按模块独立扩缩容（如大促期间单独扩容通道连接器与消息队列消费者）。

## 9. 外部接口设计

### 9.1 HTTP API

- **鉴权**：`X-App-Key` + `X-Timestamp` + `X-Nonce` + `X-Signature`（HMAC-SHA256），签名串按 `HTTPMethod\nURI\nQueryString\nCanonicalHeaders\nBody` 拼接生成；时间戳有效期 5 分钟，nonce 防重放。
- **核心接口**：单条发送、批量发送、状态查询、模板列表、签名列表、余额查询。
- **响应格式**：统一 `{code, message, data, timestamp, traceId}` 结构，便于问题追踪。
- **限流**：按 App Key 维度可配置秒/分/时/日四级限流，超限返回 HTTP 429。
- **Webhook 回调**：状态报告回调、上行消息回调，失败自动退避重试，控制台可查看失败记录并手工重推。

### 9.2 CMPP 协议接入

- **上游（平台 → 运营商）**：CMPP 长连接客户端，支持窗口控制、心跳与断线重连，用于对接移动等运营商官方或通道商网关。
- **下游（机构 → 平台）**：平台自建 CMPP Server 网关，支持 CONNECT/SUBMIT/DELIVER/ACTIVE_TEST/TERMINATE 标准流程；通过 Service_Id/TLV 扩展字段传递产品与模板编码，纳入统一的签名/模板合规校验与路由链路，与 HTTP 入口共享同一套中台能力（不作为绕开合规的旁路通道）。

### 9.3 黑名单检测（第三方风险名单服务）接口约定（参考现有对接文档）

- 单号检测：`POST {host}/api/check/v2/forbid`，参数含 `appId`、`callee`（被叫号码）、`level`（检测等级 1-3）、`score`（黑名单基准分值，默认 85）、`timestamp`、`sign`；返回 `code/msg/data{requestId, callee, calleeVolley, source, supportIpMsg}`，`calleeVolley=true` 即命中黑名单，`source` 标识拦截原因分类。
- 批量检测：`POST {host}/api/check/v2/batch/forbid`，`callee` 以逗号分隔（单批最多 500 个），响应含 `singleRespList` 逐条结果。
- 平台路由引擎在 F-5.1/F-5.3 中对接此类服务，作为黑名单检测的数据源之一。

### 10.12 数据留存与归档策略

**核心要求：业务数据留存 2 年以上。**

| 数据类型 | 在线留存 | 归档策略 |
|---|---|---|
| 发送详单 / 提交详单 / 回执详单 | 建议热数据 3-6 个月（数据库分区表，按月分区） | 超期数据归档至低成本对象存储（如按月导出为压缩文件），保留至满 2 年以上；归档数据支持按需检索恢复，检索时效可适当放宽（如 T+1） |
| 上行详单 / 退订记录 | 同上 | 退订记录属合规稽核证据，归档后仍需保证可检索，建议不短于 2 年 |
| 批量任务及明细 | 建议热数据 3-6 个月 | 归档至满 2 年以上 |
| 短链审核记录 | 长期在线（短链有效期内需持续可查） | 短链过期后归档，满 2 年以上；跳转目标变更巡检记录一并归档留痕 |
| 操作日志 / 安全审计日志 | 建议热数据 6-12 个月 | 归档满 2 年以上，涉及安全合规审计的日志按更长周期或法规要求保留 |
| 计费流水 / 对账结算数据 | 长期在线（财务追溯需求高） | 满 2 年后可归档但需保证可追溯查询，涉及税务/审计要求的可延长至 5 年以上（待财务确认） |
| 投诉占比统计视图 | 长期在线（体量小，聚合后已脱离明细） | 按需保留，作为历史投诉趋势追溯依据，无强制归档需求 |
| 统计聚合表 | 长期在线（体量小，聚合后已脱离明细） | 按需保留，无强制归档需求 |

- 归档与在线数据分离设计，避免明细表随时间无限增长影响热数据查询性能（结合 6.1 节的高 TPS 要求，发送详单表必须按时间分区 + 定期归档，防止单表数据量过大拖慢路由与查询链路）。
- 归档数据需支持导出管理模块（F-7.8）按需检索与导出，满足客户历史数据查询、稽核与合规审计需求。

## 11. 项目验收标准（Definition of Done）

1. **功能完整性**：本 PRD 第 5 章所列功能点在对应实施阶段全部交付并通过测试用例验收。
2. **通路真实可用**：至少完成 2 个上游通道（不同协议）与 HTTP + CMPP 两种下游接入方式的真实联调，能够真实发送短信并正确处理运营商回执。
3. **合规闭环**：签名/模板未审核通过无法用于发送；黑名单命中号码（系统级/机构级/第三方任一命中）在路由阶段被正确拦截且有据可查；退订关键词能在上行消息中被正确识别并使号码自动进入黑名单、生成退订记录；短链在审核通过前不可跳转至目标地址。
4. **计费准确**：预付费实时扣费与后付费账期结算的金额与详单在抽样对账中一致率 100%。
5. **性能达标**：压测验证峰值 1000 条/秒的处理能力，且日处理量不低于 10 万条基线；核心 API 响应时间与系统可用性达到 6.1 节指标。
6. **数据留存**：核心业务数据（详单、计费、日志）满足 2 年以上留存要求，归档与检索机制验证通过；敏感字段按 6.2.1 节要求加密存储，抽样核查通过。
7. **角色分权验证**：系统管理员、运营、财务、机构用户四类角色的功能边界与数据权限符合第 3 章定义，越权访问被正确拒绝。
8. **生命周期闭环**：机构从注册、试用、签约、月度对账、费用预警、投诉预警到终止的全流程（第 12 章）可在系统中完整跑通，无需人工线下补漏。
9. **投诉占比看板生效**：通道/机构月度投诉占比看板（F-11.9）能正确计算占比并对超阈值数据标红高亮，联动告警与暂停操作验证通过。

## 12. 配套管理流程

> 本章从"端到端业务流程"视角，串联第 5 章中分散在各功能模块（F-2/F-4/F-5/F-8/F-9/F-11 等）的功能点，分别描述机构（客户）侧的全生命周期与平台内部的日常运营管理主线，作为需求评审时检验"功能点是否能拼接成完整业务闭环"的依据。

### 12.1 机构（客户）全生命周期（六阶段）

```
① 注册（含试用） → ② 正式签约 → ③ 月度对账/详单/上行返回 → ④ 费用预警 → ⑤ 日常投诉预警与暂停 → ⑥ 停止合作
```

#### 阶段一：注册（含试用）

| 项目 | 内容 |
|---|---|
| 提交资料 | 企业简称、企业全称、营业执照、法定代表人身份证（正反面）、联系人姓名、联系人身份证号、联系人手机号、**短链域名所有权证明**、**商标所有权证明**（详见 F-2.1、第 10.2 节数据字典） |
| 审核 | 运营人员审核资料真实性（F-2.2），通过后自动开通"试用"状态账号 |
| 试用配置 | 系统为机构配置**试用条数额度**与**试用有效期**（F-2.8），试用期内可发送但额度用尽或到期自动冻结 |
| 关联功能 | F-2.1、F-2.2、F-2.8 |
| 关键数据 | tenant_info 资质字段、试用额度与有效期字段（10.2 节） |

#### 阶段二：正式签约

| 项目 | 内容 |
|---|---|
| 触发条件 | 机构在试用期内或到期后申请转正式，或运营主动推动签约 |
| 确定要素 | **计费模式**（预付费/后付费）、**价格**（产品单价/阶梯价）、后付费授信额度与账期、合同编号与附件 |
| 关联功能 | F-2.9（签约管理）、F-2.5（计费模式设置） |
| 状态变化 | 机构状态由"试用"→"已签约"，解除试用额度限制 |

#### 阶段三：每月对账 / 详单 / 上行返回

| 项目 | 内容 |
|---|---|
| 对账单生成 | 财务按账期（月结/季结）生成对账单，含发送量、成功量、计费量、应收金额（F-8.5） |
| 详单支撑 | 机构可自助查询/导出发送详单、群发详单、回执详单核对账单明细（F-7.2~F-7.4、F-7.8） |
| 上行数据返回 | 机构侧查询本机构上行消息与退订记录，用于自身用户运营（F-7.5、F-7.9、F-10） |
| 建议实践 | 系统按账期自动打包生成"对账单 + 详单汇总 + 上行/退订汇总"三件套，推送财务与机构双方线上确认，减少人工对账 |
| 关联功能 | F-8.5、F-7.2~F-7.5、F-7.8、F-7.9、F-10 |

#### 阶段四：费用预警

| 项目 | 内容 |
|---|---|
| 预付费场景 | 账户余额低于设定阈值（金额或预计可用天数）时预警 |
| 后付费场景 | 消费金额接近授信额度设定比例（如 80%/95%）时预警 |
| 通知对象 | 机构（自助续费/申请提额）、财务、运营 |
| 关联功能 | F-8.10（费用预警） |

#### 阶段五：日常投诉预警与暂停

| 项目 | 内容 |
|---|---|
| 监控指标 | 投诉率、发送失败率、退订率等机构级风险指标持续监控，**并参考 F-11.9 机构投诉占比看板** |
| 预警与处置 | 超过阈值先预警，屡教不改或严重违规可联动暂停该机构发送权限（保留查询/对账能力），恢复需人工复核 |
| 关联功能 | F-9.5（机构级投诉预警与自动暂停）、F-9.3（投诉联动处置）、F-11.9 |

#### 阶段六：停止合作

| 项目 | 内容 |
|---|---|
| 触发场景 | 主动终止、严重违规、长期欠费、资质到期未续 |
| 处置动作 | 停止受理新提交、吊销/冻结 API Key 与 CMPP 凭证、下线签名模板、完成账务结清 |
| 数据处理 | 终止后历史数据仍按 10.12 节留存策略保留 2 年以上，满足稽核要求 |
| 关联功能 | F-2.10（停止合作） |

### 12.2 平台内部运营管理（三条主线）

#### 主线一：投诉监督与通道暂停

- 运营人员日常处理投诉工单（F-9.1/F-9.2），对涉事号码/机构/签名/模板做联动处置（F-9.3）。
- 当投诉集中指向某一上游通道（如某通道商号码被大量举报为诈骗/骚扰），或该通道在"通道投诉占比看板"（F-11.9）中被标红超标时，运营可直接暂停该通道（F-4.7），触发路由引擎自动切换备用通道（F-5.9），问题解决后手工恢复。
- 机构级投诉率异常（含"机构投诉占比看板"超标）时按 F-9.5 触发预警乃至自动暂停该机构。

#### 主线二：费用监管 / 对账 / 暂停

- 财务通过 F-8.10 费用预警实时掌握各机构余额/授信使用情况，异常提前介入。
- 按 12.1 节阶段三的月度对账流程与机构核对账单，标记并处理差异（F-8.5）。
- 严重欠费或长期拖欠账期的机构，财务可发起冻结（F-2.4 机构状态管理）直至结清或转入终止流程（F-2.10）。

#### 主线三：通道监督与路由政策配置

- 运营通过通道监控（F-4.3）、通道统计（F-4.5）与"通道投诉占比看板"（F-11.9）持续评估各上游通道的成功率、时延、成本与合规表现。
- 基于评估结果动态调整分流规则、权重与主备策略（F-5.8/F-5.9），实现成本与成功率的平衡优化。
- 通道异常（健康检查失败、投诉集中、投诉占比超标、成本异常）时执行暂停/恢复（F-4.7），并结合告警规则（F-12.1）做到问题早发现、早处置。

## 13. 风险与依赖

| 风险/依赖 | 说明 | 应对建议 |
|---|---|---|
| 上游运营商/通道商对接周期不可控 | 真实联调、报备审核依赖外部方配合，存在延期风险 | 优先与至少 2 家通道商并行推进，避免单点依赖阻塞整体进度 |
| 签名/模板监管政策变化 | 2025 年起三大运营商陆续强化签名实名制、模板预审新规 | 审核流程与数据模型预留扩展字段，便于跟进政策调整 |
| "单日10万条"与"1000条/秒"指标口径不一致 | 详见 6.1 节说明 | 需求评审阶段与业务方确认真实容量诉求，避免容量规划偏差 |
| 第三方黑名单服务可用性 | 路由前置依赖外部接口，若不可用可能影响发送链路 | 按 F-5.3 设计超时降级策略，避免单点故障拖垮主链路 |
| 2 年以上数据留存对存储成本的影响 | 明细数据量随 TPS 增长快速膨胀 | 依据 10.12 节分区+归档策略，冷热分离控制在线存储成本 |
| 多协议通道对接的开发与维护成本 | CMPP/SGIP/SMGP 协议差异大 | 采用连接器插件化架构（4.5/6.5 节），降低新增协议的边际成本 |
| 退订记录、短链审核在现有参考实现中尚未落地 | 对照《短信手册 平台端.docx》与《短信手册 用户版.docx》页面截图逐一核对后发现：上行详单/黑白名单等页面均未见"退订"专用标记字段，短链模块也未见"审核"环节，二者为本次增补的净新功能（F-7.9/F-10.2、F-13.2） | 排期时按新功能对待，预留独立的设计评审与测试用例，不可假设可直接复用现有代码 |
| "千分之三"投诉占比阈值来源待确认 | 用户原始表述"千万三"存在歧义，本 PRD 按行业常见的千分之三（0.3%）理解并设为可配置默认值（见 5.11 节 F-11.9 说明） | 评审时与业务方确认阈值真实来源（如是否引用某运营商/监管具体标准），确认后更新默认值 |
