# 前端页面实现与验收规范

本文是 YCSOPEN-SMS Web 管理端的统一实现约定，也是 UI 缺陷 issue 的验收基线。目标浏览器为本机 Chrome（不承诺其它浏览器）。

## 页面骨架

- 所有登录后页面使用统一侧栏、面包屑、页面标题和内容容器；主内容从侧栏右侧开始，容器宽度随窗口缩放，不能产生横向滚动。
- 页面标题、说明、右上角页面级动作位于同一页头区域；页头动作不得覆盖标题或说明。
- 内容按“查询/操作区 → 数据区”分组为卡片，卡片之间保持一致的垂直间距；一页有多个业务区时，每个区必须有清晰小标题。

## 查询与表单

- 查询区使用 `data-testid="query-panel"`，筛选字段放在 `data-testid="query-fields"`，动作放在 `data-testid="query-actions"`。
- 查询表单中的每个字段都按“文字标签 → 控件”的顺序横向排列，标签位于输入框、下拉框、文本区或文件上传控件的左侧；标签与控件垂直居中，不能把标签单独放到控件上方。
- 所有查询组件按业务顺序从左到右排列；一行放不下时自然换行。换行后，第 N 个组件在各行保持同一左侧起点，形成规整的列对齐，不得因内容长度导致每行错位。
- 输入框（含日期和数字输入）预留不少于 30 个汉字的可输入宽度；下拉框宽度按其最长 option 文本加统一左右内边距确定，不能截断选项或明显短于选项内容；文本区和文件上传控件遵循相同的标签、列对齐规则。
- 查询、重置等动作固定放在查询组件的最后一行，并与该行最后一个组件的右边缘对齐；动作不得漂浮在查询区上方、挤入表头或单独占用不相关列。
- 文本框、日期框、下拉框和多行框的可视高度统一为 40px（多行框按内容需要增高但不得小于 40px）；下拉框文字、箭头和边框垂直居中，不能出现矮小控件。
- 所有 button 使用统一高度并与输入控件成比例，默认与 40px 控件高度一致（允许误差 ±2px）；同一动作行中的按钮不得互相高低不齐。
- 每个输入控件必须有可见 label、稳定的 `data-testid` 和明确用途；无对应查询、提交或联动行为的孤立输入框不得保留。
- 查询、重置、刷新等按钮放在同一动作区，按钮高度与控件一致；查询表单换行时动作仍保持在最后一行的右侧，不得挤入表头。
- 新建/编辑表单使用 `data-testid="entity-form"`，提交和取消动作使用 `data-testid="form-submit"`、`data-testid="form-cancel"`；必填项、错误提示和提交禁用状态可被 Playwright 定位。

## 表格、空状态与弹窗

- 数据区使用 `data-testid="data-table"`；表头始终渲染，即使没有数据。空数据时使用跨列空状态行 `data-testid="table-empty"`，不得只显示一句无结构文本。
- 表头、单元格和操作列保持统一内边距与行高；长文本截断并提供 title/详情动作，不能导致列挤压或页面横向溢出。
- 弹窗根节点使用 `data-testid="modal"`，关闭、确认、取消动作分别提供稳定 test-id；浮件/下拉面板使用 `data-testid="popover"`。
- 每一个可点击、可输入、可选择、可分页和可导出的元素都必须有稳定且语义化的 `data-testid`，不得使用随机 id 或仅依赖文案定位。

## 登录页

- 登录卡片使用 `data-testid="login-card"`，用户名、密码、记住用户名和提交按钮分别可定位。
- 复选框的可视尺寸为 16px 左右，标签单行显示；卡片内字段间距一致，错误提示不推动按钮溢出卡片。

## Chrome + Playwright 验收

每个页面至少验证：页面标题可见；`query-panel`（如有）内每个字段均满足“左侧 label、右侧控件”；输入控件宽度不少于 30 个汉字，下拉框不截断最长 option；所有控件按顺序从左到右排列，换行后各行第 N 个组件左边缘对齐；所有控件和 button 高度为 40px±2px；查询/重置动作位于最后一行右侧并与最后一个组件右边缘对齐；`data-table` 的表头可见，空数据时 `table-empty` 可见；页面无横向滚动。登录页额外验证 `login-card`、复选框尺寸和提交成功后跳转。验收脚本只使用 Chrome，并优先使用上述 test-id。
