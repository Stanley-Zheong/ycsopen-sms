# Shared Query Panel UI Elements (Issues 58 and 64)

This production-change addendum defines the shared query-panel contract from
GitHub issues #58 and #64. It does not replace or relabel evidence from completed GSD
phases. Existing phase-owned selectors remain on their controls and tables;
the shared selectors below add one consistent interaction contract that tests
scope within each `query-panel` region.

The field grid has two columns at the production desktop viewport and one at
the compact viewport. The non-wrapping action group sits beside the first field
row. A panel starts collapsed whenever its field count would occupy more than
one row in the current grid, and exposes `query-panel-toggle`. The disclosure
region contains both fields and actions, so they expand and collapse together.
A one-field panel renders search without reset. A multi-field panel also
renders reset, which clears the query draft, applies the empty query, and
restores the first page where the page is paginated.

Every panel uses `query-panel`, `query-panel-fields`, `query-submit`, and
`query-result-table`. A multi-field panel also uses `query-reset`; a
collapsible panel also uses `query-panel-toggle`. Each field uses `query-label-<name>` and
`query-input-<name>`; `<name>` is the stable filter key listed below.
`query-input-<name>` identifies the field's control region and contains exactly
one native input/select/textarea; browser tests scope to that descendant. The
pre-existing page-specific selector remains on the native control. Likewise,
the generic action selector is on the native button, while an old action
selector, where needed, remains as a nested click-compatible alias.

The inventory covers page-level list queries. Action forms and embedded
submodule controls retain their existing ownership; in particular, the
keyword-library tenant selector on `/admin/unsubscribes` is an immediate
submodule selector rather than the page's unsubscribe-evidence query. The
three representative Chrome obligations have unique IDs below. Other rows
link to their existing phase Playwright owner, which continues to exercise
the page-specific permission and API contract after the shared component
migration.
