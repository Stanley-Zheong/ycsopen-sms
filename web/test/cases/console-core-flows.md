# Web 控制台核心流程测试用例

## 范围与证据

- 产品基线：`docs/PRD.md` v1.3.0 中 F-1.4、F-2.1/F-2.2/F-2.8、F-4.1/F-4.7、F-6.10、F-11.9。
- 使用入口：`docs/使用手册.md` 的“登录与基本使用”。
- 实现基线：`web/src/pages`、`web/src/components/layout`、`web/src/api` 和 `web/src/router/routes.tsx`。
- 自动化环境：Node.js 20+；Playwright 启动本地 Vite；后端请求由每个用例独立 mock，不读取或修改共享数据。
- 已知边界：F-6.10 当前仍调用 HMAC 保护的 `/api/v1/sms/send`，真实 JWT 控制台发送尚未打通；自动化只验证当前页面对成功和失败响应的呈现。

## WEB-AUTH-001 管理员登录分流

前置条件：全新浏览器上下文；登录接口可返回 `ADMIN` 会话。

1. 打开 `/login`，在“用户名”输入 `admin`，在“密码”输入有效密码，点击“登录”。
2. 观察地址和页面标题。

预期结果：请求体包含输入的用户名与密码；地址变为 `/admin/dashboard`；页面显示“关键指标概览”和平台侧导航。登录接口为只读 fixture，无业务数据清理。

## WEB-AUTH-002 机构管理员登录分流

前置条件：全新浏览器上下文；登录接口可返回 `TENANT_ADMIN` 且 `tenantId` 非空的会话。

1. 打开 `/login`，输入机构管理员账号和有效密码，点击“登录”。
2. 观察地址和页面内容。

预期结果：地址变为 `/tenant/overview`；页面显示“账户总览”和机构端导航。登录接口为只读 fixture，无业务数据清理。

## WEB-AUTH-003 登录失败

前置条件：全新浏览器上下文；登录接口返回 401。

1. 打开 `/login`，输入无效用户名和密码，点击“登录”。
2. 观察地址、错误提示和受保护内容。

预期结果：仍位于 `/login`；显示“用户名或密码错误，或账号已被锁定”；不出现平台或机构导航。失败请求不产生服务端 fixture，无需清理。

## WEB-DASH-001 投诉占比看板展示

前置条件：已通过 ADMIN 登录；通道接口依次返回“移动主通道”（发送量 1000、投诉量 3、`ratio=0.003`、`overThreshold=true`）和“联通备用通道”（发送量 2000、投诉量 2、`ratio=0.001`、`overThreshold=false`）；机构接口返回“示例机构”（发送量 500、投诉量 1、`ratio=0.002`、`overThreshold=false`）。返回顺序视为后端排序契约。

1. 进入“数据概览（仪表盘）”。
2. 分别观察“每通道当月投诉占比”和“每机构当月投诉占比”。
3. 检查超阈值行、角标、发送量、投诉量和投诉占比。

预期结果：两个看板均出现；“移动主通道”整行高亮并显示可见文本“超阈值”，发送量/投诉量显示 `1,000`/`3`，投诉占比显示 `3.00‰`；通道卡显示“1 项超阈值”；“联通备用通道”显示 `1.00‰` 和“正常”；“示例机构”显示 `2.00‰` 和“正常”。只读 fixture，无需清理。

## WEB-DASH-002 投诉占比请求失败

前置条件：已通过 ADMIN 登录；两个投诉占比接口均返回 500。

1. 打开平台仪表盘。
2. 等待两个请求完成。

预期结果：两个卡片均显示“加载失败，请稍后重试”；页面不崩溃。失败请求不产生数据，无需清理。

## WEB-TENANT-001 审核机构并开通试用

前置条件：已通过 OPERATOR 登录；机构列表首次返回一条 `PENDING/SUBMITTED` 机构，审核成功后返回 `VERIFIED/TRIAL`，下一次列表读取相同最终状态。

1. 点击“机构管理”。
2. 在待审核机构行点击“审核通过并开通试用”。
3. 捕获审核请求并等待列表刷新。

预期结果：请求路径包含机构 ID；查询参数为 `approvedBy=operator-demo`、`trialQuota=500`、`trialDays=14`；刷新后认证状态为 `VERIFIED`、生命周期状态为 `TRIAL`，审核按钮消失。mock fixture 随浏览器上下文销毁。

## WEB-CHANNEL-001 暂停正常通道

前置条件：已通过 OPERATOR 登录；通道列表首次返回一条 `NORMAL` 通道，暂停成功后下一次列表返回 `PAUSED`。

1. 点击“通道管理”，在正常通道行点击“暂停”。
2. 在浏览器提示框输入“投诉率超阈值”并确认。
3. 捕获暂停请求并等待列表刷新。

预期结果：请求路径包含通道 ID；查询参数包含输入原因和 `operatedBy=operator-demo`；刷新后状态为 `PAUSED`，操作变为“恢复”。mock fixture 随浏览器上下文销毁。

## WEB-CHANNEL-002 恢复暂停通道

前置条件：已通过 OPERATOR 登录；通道列表首次返回一条 `PAUSED` 通道，恢复成功后下一次列表返回 `NORMAL`。

1. 点击“通道管理”，在暂停通道行点击“恢复”。
2. 捕获恢复请求并等待列表刷新。

预期结果：向对应通道的 `/resume` endpoint 发起 POST；刷新后状态为 `NORMAL`，操作变为“暂停”。mock fixture 随浏览器上下文销毁。

## WEB-SEND-001 手工发送成功呈现

前置条件：已通过 TENANT_USER 登录；发送接口返回消息 ID `msg-001`。

1. 点击“发送管理”。
2. 在“手机号”输入 `13800138000`，在“模板ID”输入 `1001`，点击“发送”。
3. 捕获请求体并观察结果。

预期结果：请求体包含手机号、模板 ID 和空的 `templateParams`；页面显示“提交成功，消息ID：msg-001”。mock fixture 随浏览器上下文销毁。

## WEB-SEND-002 手工发送失败呈现

前置条件：已通过 TENANT_USER 登录；发送接口返回 HTTP 400，响应 JSON 的 `message` 为“余额不足”。

1. 打开“发送管理”，填写手机号和模板 ID 后点击“发送”。
2. 观察结果区域。

预期结果：页面显示“提交失败：余额不足”，不显示成功消息 ID。失败请求不产生数据，无需清理。

## WEB-AUTH-005 机构角色访问平台页面被拒绝
